## 개인 회고 (Retrospective)

이번 자율 챌린지는 평소 실무와는 다른 성격의 경험이었습니다.  
짧은 시간 안에 혼자 모든 것을 판단하고 구현해야 했기에 당황하기도 했지만, 집중해서 결과물을 만들어내는 과정은 신선했고 재미있었습니다.  
특히 접근성을 직접 스크린리더로 검증해본 것은 실무에서 잘 접하지 못했던 색다른 도전이었습니다.  

### 배운 점과 아쉬운 점
- **준비 단계의 중요성**  
  시작 전 파일 구조를 충분히 확인하지 않아 30분 정도 늦게 작업을 시작했습니다.  
  다음에는 초반 10분을 투자해 환경과 요구사항을 먼저 정리해야 함을 깨달았습니다.

- **기술 선택의 일관성**  
  처음에는 `<div>`로 모달을 구현하다가 뒤늦게 `<dialog>`로 전환하면서 불필요한 리팩터링이 발생했습니다.  
  앞으로는 사용할 태그와 API를 미리 확정하고 진행할 계획입니다.

- **스타일링 최소화 전략**  
  Tailwind를 설치해두고도 실제 적용을 많이 하지 못했지만, 이번에는 접근성 검증에 집중하기 위해 스타일링은 최소화하는 쪽으로 우선순위를 두었습니다.  
  다음에는 접근성과 기본 디자인 모두를 균형 있게 챙기도록 준비하겠습니다.

- **접근성 테스트 경험**  
  VoiceOver와 TTS(Read Aloud)를 활용해 접근성을 직접 검증해 보았습니다.  
  하지만 크롬 익스텐션만으로는 한계가 있었고, 기대와 다르게 동작하는 부분도 있어 보조기술 테스트의 필요성을 절실히 느꼈습니다.

- **완성도에 대한 아쉬움**  
  주어진 시간 내에 모든 기능을 구현하지 못했고, 코드의 가독성도 부족했습니다.

### 다음을 위한 구체적인 계획
- **준비 단계 강화**: 환경 설정 점검뿐 아니라 핵심 기능 한두 개를 미니 프로토타입으로 먼저 구현해 예상 문제를 파악하겠습니다.  
- **기술 선택의 일관성**: `<dialog>`처럼 의미 있는 태그를 미리 확정하고, 관련 API와 속성을 조사해 불필요한 리팩터링을 줄이겠습니다.  
- **효율적인 스타일링과 접근성 균형**: Tailwind 같은 유틸리티 CSS 프레임워크를 미리 연습해 기본 스타일링은 빠르게 적용하고, 더 많은 시간을 기능 구현과 접근성 테스트에 집중하겠습니다.  
- **접근성 테스트 숙련**: 크롬 익스텐션을 넘어서 VoiceOver, NVDA 등 실제 스크린리더를 익히고, ARIA 속성과 시맨틱 구조가 어떻게 인식되는지 깊이 학습하겠습니다.  

### 포커스 트랩(Focus Trap) 경험

이번 챌린지를 통해 모달 접근성에서 **포커스 트랩(Focus Trap)** 개념과 구현의 중요성을 깨달았습니다.  

포커스 트랩은 모달 창이 열렸을 때 키보드 포커스가 모달 내부에만 머무르도록 제한하는 기술입니다.  
이 기능이 없다면 키보드 사용자나 스크린리더 사용자는 모달 외부까지 포커스가 이동해버려 혼란을 겪을 수 있습니다.  
즉, 모달이 닫히기 전까지 사용자는 모달 안에서만 탐색할 수 있어야 하며, 이는 웹 접근성에서 매우 중요한 요소입니다.  

실제로 구현할 때는 다음과 같은 방식으로 진행했습니다:

```ts
const focusableElements = dialogRef.current?.querySelectorAll(
  'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
) as NodeListOf<HTMLElement>;

if (focusableElements && focusableElements.length > 0) {
  const first = focusableElements[0];
  const last = focusableElements[focusableElements.length - 1];

  // Tab → 마지막에서 처음으로 순환
  if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }

  // Shift+Tab → 처음에서 마지막으로 순환
  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  }
}

---

이번 경험은 완성도 면에서는 아쉬웠지만, 접근성 중심의 개발과 시간 압박 속 의사결정을 직접 체감할 수 있던 값진 기회였습니다.
